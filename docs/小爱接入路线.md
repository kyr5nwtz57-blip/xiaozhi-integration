# 小爱音箱接入小智 · 路线分析

> ⚠️ 本文为**技术路线分析**，非操作手册。具体型号差异请以实测为准。

## 核心问题

小爱音箱是**封闭设备**：官方固件只连小米自己的云，不接受第三方替换。
要让它接入小智，本质上有三类思路。

## 路线 A：外挂旁路（推荐，零风险）

**不改小爱硬件/固件**，在局域网里插一个"中间人"设备（树莓派 / 旧手机 / 本项目的 Mac）。

```
你说话 → 小爱音箱（当麦克风+扬声器用）→ 中间人 → 小智云端 → 中间人 → 小爱播放
```

- **优点**：不动小爱，随时可退；本仓库的 `src/` 可直接复用
- **难点**：怎么把音频从"小爱"引出来。可选：
  - 小爱开放平台的**自定义技能**（受限，时延大）
  - 蓝牙/AUX 输入（部分型号支持）
  - 直接用小爱当纯音箱（蓝牙配对），麦克风另接

## 路线 B：刷机改固件

给小爱刷第三方固件（如 OpenWrt 类改造、或直接刷 ESP32 兼容固件），把它变成"官方小智固件"
能跑的设备。

- **优点**：体验最原生，直接跑官方协议
- **风险**：**变砖**、失去保修、型号兼容性差异极大
- **前提**：确认具体型号有成熟刷机方案（社区支持度）

## 路线 C：DNS/流量劫持

在路由器上劫持小爱的域名解析，把它的云端请求转发到自建服务器。

- **优点**：理论上最透明
- **难点**：小爱通信有**证书校验 + 固件签名**，现代版本基本堵死；且违反服务条款

## 本仓库的定位

本仓库沉淀的是**协议层与音频层的完整实现**（`src/xiaozhi.py` 等）。
**无论走哪条路线，这几块都是必需的**：

- 与小智云端的 WebSocket 协议交互 ✅ 已有
- Opus 编解码 ✅ 已有
- 回声消除（免提场景必需品）✅ 已有
- OTA 与设备绑定 ✅ 已有

**缺的是"设备侧适配"**：把你选定的硬件（小爱 / 树莓派 / 其他）的麦克风与扬声器
接到本仓库的 `AudioEngine` 上。

## 建议的第一步

**先明确你的小爱具体型号**，然后：
1. 查该型号是否有成熟的**音频引出**方案（AUX / 蓝牙 / 开放平台技能）
2. 若有 → 走路线 A，本仓库代码直接用
3. 若无 → 评估路线 B 的刷机可行性

## 最小验证路径

先不用管小爱。用**电脑**跑通 `src/xiaozhi.py`：
- 能连上、能对话、能连续多轮
这一步通了，协议层就没问题了，剩下的只是"换硬件"。
