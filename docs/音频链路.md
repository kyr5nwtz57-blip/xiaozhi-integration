# 音频链路

## 采样率不对称

| 方向 | 采样率 | 格式 | 帧长 |
| :--- | :--- | :--- | :--- |
| 上行（麦克风→服务器） | **16000 Hz** | Opus, 单声道 | 60 ms |
| 下行（服务器→扬声器） | **24000 Hz** | Opus, 单声道 | 60 ms |

**上下行采样率不同**，解码器必须按服务器 hello 里返回的 `audio_params.sample_rate` 构建。
中途若采样率变化，**只换解码器，不要重建整个音频引擎**——编码器必须全程唯一，
否则 Opus 的 pts 会重置、预热丢失。

## Opus 分帧

60ms @ 16kHz = 960 样本/帧。

用 PyAV 编码时，`CodecContext` 无法设置 `frame_duration`，**实际每个 60ms 输入帧会被
拆成 3 个 20ms Opus 包**。这与声明的 60ms 语义等价（总时长一致），服务端 STT 正常工作。
**不要试图"修复"这个行为**——它无害。

## 重采样

下行 24kHz → AEC 需要的 16kHz 参考信号，需要重采样。
优先用 `scipy.signal.resample_poly`（多相滤波，质量好）；scipy 缺失时退回线性插值。

```python
from fractions import Fraction
from scipy.signal import resample_poly

frac = Fraction(16000, 24000)   # 2/3
y = resample_poly(x, frac.numerator, frac.denominator)  # up=2, down=3
```

## 播放队列

下行 Opus 解码后的 PCM 必须**严格保序**。

⚠️ 常见 bug：用 `queue.Queue` 做播放缓冲时，如果一次回调取不完一个 chunk，
把剩余部分 `put_nowait` 回队列**尾部** → 采样顺序颠倒 → 声音破碎。

**修法**：用连续线性缓冲（deque + appendleft，或 numpy 拼接），保证样本严格时间顺序。

## 抗抖动

网络抖动会导致播放断续。建议在播放前加 **150ms 左右的预缓冲**，
队列积够再开始播，避免每帧都在"等下一包"。
